# AlgoTop · 算法面经实验室

面向搜广推、NLP、LLM、VLM、营销算法的可追溯复习网站。当前为可本地运行并部署到 GitHub Pages 的静态网站，不是公司官方题库，也不是全网题库。最新规模以界面和数据审计报告为准。

## 启动

无需安装依赖，Node.js 用于测试与数据工具，Python 用于本地服务：

```sh
cd algotop
npm test
python3 -m http.server 8766 --bind 127.0.0.1
```

在运行该命令的同一台电脑打开 http://127.0.0.1:8766/ 。不要直接双击 HTML，因为浏览器可能阻止本地 JSON 模块加载。手机上的 localhost 并不指向 dot 电脑。

## 内容如何理解

- 综合题是按准备范围归并的复习卡，不表示每个关联来源逐字问过卡片的每个子问题。
- 原始问法为改述，附出处。个人自述只代表该作者的记录，不代表公司承认、当前招聘范围或面试题真实性已独立验证。
- 来源提及数以去重文档为单位。多轮合集不是一场面试，多次追问不是多个独立样本。不能将来源提及数换算成真实考频或通过率。
- 二次汇编单独标注，不混入一手来源计数；只检索到片段但未核验正文的候选来源不加入正式题库。
- 来源日期、作者报告的面试日期、采集日期不同。缺失年份不推断；网站更新日期不代表题目都是近期题。
- 参考答案是另行撰写的学习材料，不是原作者/公司标准答案。已核对主要论文及文档，但尚未经人工专业审核；面试前应沿引用复核。公式和代码的适用前提以题解为准。
- 当前覆盖不均衡，不以虚构公司、日期或重复问题凑数。

## 数据文件

- `data.json`：来源、综合题、原始问法改述、归并理由及资格标注。
- `answers.json`：基线题目的答案覆盖。
- `answers-extra.json`：扩展题目的答案覆盖。
- `scripts/` 与 `docs/DATA_PIPELINE.md`：离线校验、受控增量导入及制作流程。

数据与学习记录分离。笔记、收藏、掌握状态只保存在当前浏览器，不上传、不登录、不跨设备同步；可导出备份，导入前检查文件。清理浏览器站点数据可能丢失学习记录。静态网站中不能存放模型密钥、用户凭据或私密原帖。

## GitHub Pages

目标为公开仓库 `dqdallen/algotop`。本发布准备快照已通过本地自动测试与构建，但尚未验证远端推送和 Pages 部署成功。预期地址为 `https://dqdallen.github.io/algotop/`，这不是上线声明。

部署步骤：

1. 将公开源文件上传到目标仓库 `main` 分支，不要上传生成目录、研究中间件、备份或学习记录。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. `.github/workflows/pages.yml` 在 `main` 推送时自动运行，也可在 Actions 手动触发。它执行测试、数据审计与构建，只部署 `_site/` 中的运行文件。
4. 等待对应提交的 **Deploy GitHub Pages** 工作流成功，再打开部署输出地址验证网站和 JSON 资源；不要仅凭本地测试宣布上线。

公开源码与题库不代表公司认证或原始来源授权保证。答案仍需人工专业审核，来源权利和无障碍检查仍有待完善。账号登录、仓库和 Pages 权限由仓库所有者管理。

## v2：公司、实际岗位与学习主题分开

默认时间窗为 **2022-01-01 至 2026-10-25**。这是一批可核验公开来源，不是“全网所有算法面经”的穷尽全集，不以帖子数声称真实独立面试次数。

- `taxonomy.json` 的 `jobDirections` 是岗位分类，有父组、稳定 ID、中文名称和别名。包括信息分发/商业、语言/生成、感知/物理智能、决策/行业智能、通用机器学习等；没有样本的分类也展示 0。AI Infra 等纯工程方向仅在 `adjacentExcluded` 中记录边界，不纳入岗位筛选。
- `source.company` 和 `record.company` 保存来源明确提到的招聘公司；未提及使用 **其他**。多公司汇总允许来源使用 `companies`，每条记录必须绑定自己的公司。公司别名的规范化不代表凭空补充雇主。
- `companyEvidence = {text, location, certainty}`。`explicit` 是来源明确、`unknown` 是未知；旧题库尚未重核的归属用 `legacy` + `legacy_attribution` 标记，不把历史记录包装成原文引语。
- `jobDirections = [{id, evidence, certainty}]` 在来源和记录层均可使用；记录优先于来源，允许一岗多标签。只有岗位叙述才支持 `explicit`，审慎推断标为 `inferred`；未明确用 `unknown`。`other` 表示已明确但尚未纳入分类的算法岗位。**不能因为问了 LoRA 就标为大模型岗，问 GNN 就标为图挖掘岗。**
- `question.studyTopics` 是学习主题、多标签；`tracks` 保留用于兼容旧数据。知识标签、复习主题与真实招聘方向独立，技术如强化学习、图学习、LoRA 可归于学习内容而非自动作为岗位。
- `dateEvidence = {value, precision, basis, evidence}`：`value` 可为 `YYYY`、`YYYY-MM`、`YYYY-MM-DD` 或 `null`；`precision` 分别为 `year/month/day/unknown`。不得补造月份或日期。`basis` 明示 `interview/published/edited/published_or_edited/claimed/unknown` 等依据；发布日不冒充面试日。已知面试年月优先于发布/编辑日期。
- 2022 年前旧来源保留在“归档”；未知年份来源单列；未来日期不得进入当前窗口。默认筛选不覆盖它们，但“全部”可以复习旧卡，原有学习进度及题号不变。

公司、岗位、日期范围和搜索必须在**同一条记录**上匹配；不能把同题 A 公司视觉岗和 B 公司大模型岗拼成 A 公司大模型岗。卡片帖子数、公司徽章、岗位徽章及详情只取命中筛选的记录。

### 验证与离线构建

```sh
npm test
node scripts/data-pipeline.js
node --check app.js
node scripts/build.js
```

构建允许列表新增 `taxonomy.json`，不会发布研究中间件、候选线索或私人笔记。自动测试包含真实 app 模块的轻量 DOM 启动及筛选回调检查；它不代替真实浏览器的视觉/键盘验收。

时间范围来源可使用 `interviewDateRange: {start, end, evidence}`；年份筛选覆盖范围中的各年，详情展示范围而非伪造单次面试日期。跨越收录窗口边界的汇总应拆分为逐记录的 `interviewDate` / `dateEvidence`，避免把整篇帖子都算入窗口。记录层日期优先于来源层。新增题目的参考答案可暂缺，不能把既有答案数量当作全题库答案覆盖率。

二手汇编与待核验线索单列 `candidate` 分区：`collectionPartition:'candidate'`、`countEligible:false` 或 `qualification:'secondary_compilation'` 均不能因声称日期进入默认窗口。原卡仍可在“二手 / 待核验线索”或“全部”复习，不删除旧答案。岗位下拉数字是全部分区来源数，不声称每类已形成充分样本。

## 本轮扩充与收集工具

完整覆盖口径见 `docs/COVERAGE.md`。公开版本不包含研究过程中的候选工作记录。本轮为公开检索和原文核验整理，不宣称全网穷尽。

`tools/collection/` 提供不依赖安装包的候选归档与受控抓取工具，可用 `python3 tools/collection/ingest.py --help` 查看命令说明。默认抓取策略关闭；未接入登录态、付费API或反爬绕过。外部抓取预检未成功，因此不能把离线测试通过理解为已经自动批量抓取。

```sh
python3 -m unittest discover -s tools/collection -p 'test_*.py'
```

网站提供“收录覆盖”矩阵及“答案状态”过滤器。新增题保留明确出处，题解未完成的条目如实显示待补充；先选择“有参考答案”可只复习已写内容。
